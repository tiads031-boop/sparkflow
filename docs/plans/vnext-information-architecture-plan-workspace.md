# SparkFlow VNext 信息架构与「计划」工作区重构方案

> 状态：方案完成，待排期实施  
> 基线：以当前 `master` 为准（Phase 15 M1–M3、Study Mode M1、Planner Preview/Apply/Undo 已存在）  
> 目标：在不重复建设 Task / Course / Calendar / Planner / Focus 数据源的前提下，重构移动端主导航与时间规划体验，使 SparkFlow 从“功能入口集合”收口为“今天—计划—记录—学习—我的”五个稳定工作空间。

---

## 1. 背景与问题

SparkFlow 目前已经形成三条较完整的用户链路：

1. **效率链**：待办 → AI Planner → Timeline → Focus → 完成。
2. **记录链**：随手记 → 回顾 → AI 洞察 → 转待办 → Planner → 执行。
3. **学习链**：Course / StudyFolder → Study Home → Task / Focus → 后续 Review。

功能本身已开始成熟，但主导航仍以历史功能入口平铺为主。当前导航注册中包含：

- 今天
- 时间轴
- 待办
- 课程
- 学习
- 记录
- 看板
- 设置

其中部分默认显示、部分可选显示。随着 Study Mode、记录、Planner 等能力扩展，继续平铺会带来以下问题：

- 一级入口数量持续增加，移动端底栏拥挤；
- “课程”和“学习”概念重叠；
- “时间轴”“待办”“Planner”“看板”实际属于同一规划工作流，却被拆散；
- “设置”占据与核心业务功能相同的一级导航层级；
- 用户需要先判断“去哪个功能页”，而不是直接完成“安排、记录、学习、执行”；
- 课程表、日历、时间轴、AI 排程如果继续分别维护，容易形成重复视图和重复数据解释。

因此，本轮目标不是继续增加新的事实源或复杂模型，而是先收口信息架构与时间视图。

---

## 2. 设计原则

### 2.1 一级导航按“用户工作空间”组织

移动端底部导航固定为：

```text
今天 | 计划 | 记录 | 学习 | 我的
```

一级导航不再直接暴露 Timeline、Tasks、Courses、Settings 等具体实现模块。

### 2.2 同一数据，多种视图

Month / Week / Agenda / Timetable 不建立新数据表。

它们只是对现有数据的不同投影：

- Task
- CalendarEvent / Schedule
- Course
- Study Task
- Planner 结果

视图切换改变“怎么看”，不改变“数据是什么”。

### 2.3 不建立第二套任务、课程、日历或学习事实源

继续复用：

- Task 作为任务事实源；
- Course 作为课程事实源；
- Calendar / Schedule 作为时间事实源；
- Planner 作为排程预览与写入逻辑；
- Focus 作为执行态；
- Inspiration / Insight 作为记录与洞察事实源；
- StudyFolder 作为学习组织层。

### 2.4 优先重构壳层，再调整业务

第一批实现应尽量不改数据库，不修改 Planner 核心语义，不重做 Phase 15。

先完成：

- 导航重组；
- 计划工作区；
- 四种时间视图；
- 旧页面能力迁入新容器。

数据库结构只有在确认现有模型无法表达实际业务时再单独评估。

## 4. 「计划」工作区定位

“计划”不是简单把几个旧页面塞进一个容器，而是 SparkFlow 的统一时间规划中心。

它要回答四个问题：

1. **有什么要做？** → 待办。
2. **什么时候做？** → 周 / 日程 / 时间表。
3. **这个月整体怎么分布？** → 月视图。
4. **怎么安排更合理？** → AI Planner。

完成安排后，直接进入 Focus 执行。

---

## 5. 计划工作区顶部结构

### 5.1 沉浸式 Header

计划页不继续使用占空间较大的通用 Header，改为高密度顶部结构：

```text
第 5 周（非本周）             ◉   +   ✨   ···
2026/09/19
```

说明：

- 第一行显示当前周或当前月上下文；
- 第二行显示日期范围或当前日期；
- `◉`：切换时间视图；
- `+`：快速新建；
- `✨`：打开 AI Planner；
- `···`：更多操作。

### 5.2 视图切换

点击视图入口展开：

```text
月视图
周视图
日程视图
时间表视图
```

切换只改变表现层，不切换数据源。

### 5.3 快速新建

计划页的 `+` 与全局 Quick Add 共用能力：

```text
新建任务
新建日程
随手记
开始专注
```

不得另建第二套创建逻辑。

### 5.4 更多菜单

首批可包含：

- 跳转日期
- 回到今天 / 回到本周
- 隐藏已完成
- 课程显示设置
- 日历同步
- 导入课表

## 6. 月视图

### 6.1 目标

回答：“这个月整体忙不忙，哪些天有安排？”

### 6.2 交互结构

顶部：

```text
2026 年 9 月 ▼
```

主体为标准月历。

单个日期格不要塞入完整任务名称，优先使用简洁状态：

```text
19
● ● ●
3 项安排
```

点击日期后，在下方或 Bottom Sheet 展开当天 Agenda：

```text
9 月 19 日 · 周六

08:00  法律职业伦理
10:10  劳动与社会保障法
14:30  民法复习
18:30  完成案例分析
```

### 6.3 数据展示优先级

日期格优先显示：

1. 是否有课程；
2. 是否有固定日程；
3. 是否有已排程任务；
4. 是否存在截止任务；
5. 是否存在学习计划。

避免在月视图中渲染过多文字。

---

## 7. 周视图

### 7.1 目标

周视图是计划工作区的核心高频视图。

参考高密度移动课表的表达方式：

- 左侧真实时间；
- 顶部星期与日期；
- 中间以彩色时间块展示安排；
- 横向按天，纵向按时间。

### 7.2 时间块类型

统一展示：

| 类型 | 展示建议 |
|---|---|
| Course | 稳定课程色 + 课程名 / 地点 |
| 固定日程 | 中性或低饱和色块 |
| 手动排程 Task | 普通任务块 |
| Planner 生成 Task | 普通任务块 + 弱 AI 标记 |
| Study Task | 使用学习标识，不另建数据源 |
| 已完成 Task | 降低透明度 |
| 锁定安排 | 小锁图标，不允许普通拖动 |

### 7.3 时间块内容

移动端优先展示：

```text
民法分论
@敏行楼-301
```

空间足够时再补：

- 时间；
- 来源；
- 优先级；
- 课程 / Task 图标。

### 7.4 周切换

支持：

- 左右滑动切周；
- 点击日期头定位某天；
- “回到本周”；
- 显示第几周。

例如：

```text
第 5 周 · 单周
9/21 - 9/27
```

如果当前查看的不是本周：

```text
第 7 周 · 非本周
```

单双周显示只有在现有 Course / Calendar 数据能够可靠判断时启用；不得为了视觉效果先写死规则。

---

## 8. 日程视图（Agenda）

### 8.1 定位

日程视图不是把周视图简单压缩成一天，而是为手机纵向浏览优化的 Agenda。

### 8.2 示例

```text
9 月 19 日 星期六

现在
────────────────

08:00
法律职业伦理
敏行楼 305
08:00 - 08:50

10:10
劳动与社会保障法
中心 305
10:10 - 12:00

13:30
复习民法分论
AI Planner
预计 50 分钟

18:30
就业指导
18:30 - 19:20
```

### 8.3 行为

- 自动滚动到“现在”附近；
- 当前正在进行的事项突出；
- 点击任务进入详情；
- 点击 Course 进入课程详情；
- Planner 生成项显示来源；
- 长按 Task 可进入重新安排。

现有 Timeline 能力优先迁入该视图，而不是保留两套相似页面。

---

## 9. 时间表视图（Timetable）

### 9.1 定位

该视图针对课程密集型场景，采用“第几节课”而不是真实连续时间作为纵轴。

例如：

```text
1
08:00
08:50

2
09:00
09:50

3
10:10
11:00
```

### 9.2 课程卡片

```text
法律职业伦理
@中心-305
```

同一课程使用稳定颜色。

### 9.3 非本周课程

如果当前数据可识别单双周 / 周次，则：

- 非本周课程降低透明度；
- 卡片底部显示“非本周”；
- 默认仍保留位置以帮助用户理解固定课表。

如果现有数据无法可靠判断，则先不显示“非本周”，避免凭 UI 推断错误业务状态。

### 9.4 与周视图的区别

**周视图：真实时间轴。**  
适合任务、会议、课程、Planner 混排。

**时间表：节次轴。**  
适合学生快速浏览课程。

两者共享 Course / Calendar 数据，不重复保存。

---

## 10. 待办与看板在计划中的位置

原独立“待办”和可选“看板”不再占一级底栏。

计划工作区内增加二级入口：

```text
日历 | 待办
```

待办内部提供：

```text
列表 | 看板
```

这样：

- Task 仍使用现有 Task Store；
- 看板只是 Task 的另一种视图；
- 不建立第二套 Board 数据源。

---

## 11. AI Planner 原生整合

### 11.1 入口

计划顶部直接提供 `✨ AI 安排`。

### 11.2 输入上下文

Planner 使用当前已存在的真实信息：

- 已有课程；
- 固定 CalendarEvent；
- 已安排 Task；
- 未安排 Task；
- Study Task；
- 锁定时间块。

### 11.3 Preview

Planner Preview 后，不只显示 Sheet 文本结果。

在当前周 / 日程视图中同时渲染“预览态时间块”。

预览态必须与已提交安排明显区分。

### 11.4 Apply / Undo

继续复用现有 Preview → Apply → Undo 语义。

不因为 UI 重构改变 Planner 的后端契约。

### 11.5 可解释性

Planner 产生的任务块可显示很弱的 AI 标识。

点击后可看到：

- 原任务；
- 推荐时间；
- 当前状态；
- 是否已锁定；
- 是否可撤销。

---

## 12. 拖拽与手动调整

后续交互增强阶段支持：

- 长按 Task 时间块；
- 拖到新日期 / 新时间；
- 松开后更新现有 Task 的排程字段；
- 锁定 Course / 固定 CalendarEvent 默认不可拖动；
- 任务拖动失败时恢复原位置并提示。

首批实现不强制加入复杂拖拽，可先通过“重新安排”Sheet 完成。

## 13. 学习模块调整

### 13.1 Course 归入 Study

不再同时维持“课程”和“学习”两个一级入口。

调整为：

```text
学习
├── 学习首页
├── 课程
├── 学习文件夹
├── 复习计划
└── 学习统计
```

### 13.2 Study Mode 开关语义

Study Mode 开关不再控制“有没有学习这个底栏入口”。

它只控制高级学习功能是否启用。

关闭时：

```text
学习
└── 课程
```

开启后：

```text
学习
├── 学习首页
├── 课程
├── 学习文件夹
└── 后续复习 / 统计
```

### 13.3 在计划中查看

Course 详情提供：

`在计划中查看`

点击后：

- 跳转计划工作区；
- 选择合适时间视图；
- 定位对应日期 / 周；
- 高亮该课程。

---

## 14. 记录模块调整

记录保持 Phase 15 主链：

```text
随手记 → 回顾 → 洞察 → 转待办
```

二级结构固定为：

```text
卡片 | 回顾 | 洞察
```

自由墙不再与三者并列，而作为“卡片”的视图切换：

```text
列表 | 自由墙
```

原因：自由墙是展示方式，不是独立业务对象。

继续以服务端 Inspiration 为记录事实源。

旧 local Spark 数据/写路径在确认无业务调用后再移除，不在本方案中直接删除既有数据能力。

---

## 15. Today 首页重新定位

Today 只回答：

> “现在最值得处理什么？”

避免成为所有模块的缩略版。

建议包含：

- 当前日期 / Week Strip；
- 下一项安排；
- 今日剩余任务数量；
- 待回顾记录；
- Study 学习提醒；
- 未安排任务提醒；
- 当前可用空档；
- AI“帮我安排剩余时间”。

Today 不承担完整任务管理、完整课程管理或完整记录管理。

---

## 16. 「我的」工作区

将 Settings 从一级底栏移入“我的”。

建议包含：

- 账户；
- 外观；
- 导航与偏好；
- 通知；
- Push；
- Google Calendar / 外部同步；
- AI Provider 状态；
- 数据与隐私；
- 关于；
- 高级设置。

这样一级导航全部面向用户行为，而非系统配置。

---

## 17. 底部导航视觉规范

移动端固定五项：

```text
今天      计划      记录      学习      我的
```

建议使用：

- 图标 + 文字；
- 当前项强化；
- 不再只依赖图标识别；
- 尊重 safe-area；
- Android / PWA 均保持可点击区域至少 44px；
- 不允许导航遮挡页面底部交互控件。

“计划”页面可适度降低底栏视觉重量，但不要因沉浸式日历完全失去全局导航。

---

## 18. 视图偏好与恢复

保存纯 UI 偏好：

```ts
lastPlanView: 'month' | 'week' | 'agenda' | 'timetable'
```

用户再次进入计划时恢复上次视图。

可以继续沿用现有本地设置机制；这不是业务数据，不需要进入数据库。

同时可记录：

- 是否隐藏已完成；
- 周视图起始日；
- 默认时间范围；
- 课程色彩偏好。

首批只实现 `lastPlanView` 即可。

## 19. 推荐前端组件结构

建议新增：

```text
web/src/components/plan/
├── PlanWorkspace.tsx
├── PlanHeader.tsx
├── PlanViewMenu.tsx
├── MonthPlanView.tsx
├── WeekPlanView.tsx
├── AgendaPlanView.tsx
├── TimetablePlanView.tsx
├── PlanEventCard.tsx
├── PlanDaySheet.tsx
└── planProjection.ts
```

其中 `planProjection.ts` 负责把不同事实源统一投影为前端展示模型。

建议展示模型只存在前端：

```ts
type PlanItemKind = 'course' | 'calendar' | 'task' | 'study-task';

interface PlanItem {
  id: string;
  kind: PlanItemKind;
  title: string;
  start: Date;
  end?: Date;
  locked: boolean;
  completed?: boolean;
  sourceId: string;
}
```

注意：这是视图模型，不是新数据库实体。

## 20. 与现有代码的迁移关系

### 20.1 `web/src/navigation.ts`

目标：

- 一级注册改为 today / plan / records / study / profile；
- 保留旧 ID 迁移映射；
- 用户已有导航偏好不能直接失效；
- `timeline`、`tasks`、`courses`、`settings` 等旧入口映射到新工作区。

建议迁移：

```text
timeline → plan
tasks    → plan
board    → plan
courses  → study
sparks   → records
settings → profile
```

如果 `ActiveTab` 改名成本过高，第一阶段可以保留内部旧 ID，只先调整 UI 容器；不要为了“命名漂亮”同时重写大量状态。

### 20.2 `web/src/App.tsx`

目标：

- 降低 App.tsx 直接管理具体业务页的数量；
- 使用工作区容器承接子视图；
- Planner / Quick Add / Focus 继续复用现有全局弹层；
- StudyWorkspace 保留并成为“学习”容器的一部分。

### 20.3 `BottomNav.tsx`

目标：

- 五项固定布局；
- 图标 + 文本；
- safe-area；
- 不因用户开启更多功能而增加第 6/7/8 项。

### 20.4 Timeline / Calendar

现有 Timeline / Calendar 能力不要直接删除。

优先：

- 提取可复用数据加载逻辑；
- 迁入 Month / Week / Agenda；
- 原入口做兼容跳转；
- 稳定后再删除重复旧视图。

### 20.5 Course

Course 数据与详情保留。

“课程页”由一级入口改为 Study 内部子页面。

课程安排同时通过 Plan 的 projection 展示。

## 21. 数据投影规则

计划视图从多个已有源读取，但必须有明确优先级。

### 21.1 Course

Course / Course Schedule 用于：

- 时间表；
- 周视图；
- 日程视图。

课程本体不能被 Planner 重排。

### 21.2 CalendarEvent

固定事件用于：

- 月 / 周 / 日程。

默认视为锁定，除非当前业务明确允许编辑。

### 21.3 Task

只有存在排程时间的 Task 才进入真实时间网格。

未安排 Task：

- 保留在待办；
- 在 Today / Plan 中提示“待安排”；
- 可交给 Planner。

### 21.4 Study Task

仍然是 Task，只通过 courseId / StudyFolder 关系赋予学习上下文。

不单独建 StudySchedule。

## 22. 响应式与移动端要求

### 22.1 手机

重点：

- 360px 宽度可用；
- Android safe-area；
- 软键盘不遮挡新建 / 编辑 Sheet；
- 周视图允许横向轻量滑动；
- 时间表在窄屏仍能读到课程名；
- 底栏不遮挡最后一节课 / 最后一个 Agenda。

### 22.2 PWA

- 与 Android 使用同一信息架构；
- 保留浏览器返回语义；
- 视图偏好恢复；
- 不依赖仅原生可用能力。

### 22.3 Desktop

不作为首批主目标。

后续可让周视图利用更宽空间显示更多字段，但不要先为了 Desktop 牺牲移动端结构。

## 23. 分阶段实施

### M0：文档与结构冻结

范围：

- 本文档合入；
- 明确五个工作空间；
- 明确 Plan 四种时间视图；
- 不改运行时代码。

验收：

- INDEX / NEXT 可找到本方案；
- 与 Phase 14 / 15 / Study Mode 的边界明确。

---

### M1：主导航与 Plan 壳层

范围：

- BottomNav 固定五项；
- 新建 PlanWorkspace；
- 新建 PlanHeader / View Menu；
- 支持 Month / Week / Agenda / Timetable 空壳切换；
- 保存 lastPlanView；
- 旧入口保持兼容；
- 不改数据库。

验收：

- 360px / PWA / Android 导航无重叠；
- 用户旧导航偏好不会导致白屏；
- 五项导航可以完整访问既有核心能力；
- 切换 Plan 视图后返回可恢复。

---

### M2：真实时间数据接入

范围：

- Course；
- CalendarEvent；
- scheduled Task；
- Study Task；
- Month / Week / Agenda / Timetable 使用真实数据；
- Course 进入 Study；
- 原 Timeline 入口兼容跳转到 Plan。

验收：

- 同一事件在不同视图时间一致；
- 同一 Course 不产生重复记录；
- 未排程 Task 不错误出现在时间网格；
- 时区与本地时间不出现 8 小时偏移；
- 当前周 / 非本周定位正确。

---

### M3：Planner 原生融合

范围：

- Plan Header 打开现有 Planner；
- Preview 映射为视图中的临时块；
- Apply 后刷新真实排程；
- Undo 后视图恢复；
- Planner 45s preview 超时策略继续保留。

验收：

- Preview 不写数据库；
- Apply 后周 / Agenda 与 Task 数据一致；
- Undo 后恢复；
- 锁定 Course / CalendarEvent 不被 Planner 覆盖；
- Planner 错误不破坏当前视图状态。

---

### M4：高交互增强

范围：

- 长按 / 拖拽 Task；
- 周 / 日程快速重排；
- 课程过滤；
- 隐藏已完成；
- 更好的当前时间定位；
- 动画与视觉 polish。

验收：

- 拖拽失败可恢复；
- 只更新允许移动的 Task；
- 移动端长按不与页面滚动严重冲突；
- 不引入独立 Schedule 数据源。

## 25. 性能要求

周视图和时间表会比普通列表更重。

首批应遵守：

- 只加载当前可见时间范围；
- 不一次渲染全年事件；
- 月视图只请求/投影当前月；
- 周视图只处理当前周附近；
- 卡片内容按可见空间裁剪；
- StudyWorkspace 继续 lazy load；
- 复杂日历模块可按工作区 lazy load。

只有出现真实性能问题后再引入虚拟列表或更复杂缓存。

## 26. 风险与边界

### 风险 A：重构时把同一能力复制两份

处理：

先复用，再迁移；旧页面通过兼容入口保留一段时间。

### 风险 B：课程与 Task 在周视图重复

处理：

projection 层按来源 ID 建稳定 key；Course 与其 CalendarEvent 如果本质是同一导入来源，只展示一个主记录。

### 风险 C：Planner 预览态与真实排程混淆

处理：

预览必须有单独视觉状态；未 Apply 前不当作正式安排。

### 风险 D：移动端周视图过于拥挤

处理：

默认限制卡片文字；详情通过点击打开；不要把所有元数据直接塞进时间块。

### 风险 E：导航迁移导致老用户偏好失效

处理：

增加旧 ID → 新工作区映射，不直接清空 storage。

### 风险 F：为了单双周新增复杂模型

处理：

先使用现有 Course / Calendar 能可靠表达的内容。只有出现“同一课程在不同周确实无法正确显示”的具体业务失败后，再单独设计最小数据扩展。

## 27. 非目标

本方案不包含：

- 新建第二套 Task；
- 新建第二套 Calendar；
- 新建 StudySchedule；
- 重写 Planner 决策层；
- 重写 Phase 15 Inspiration / Insight；
- 引入向量数据库、知识图谱或 RAG；
- 为布局重构新增 hash / contract freeze / baseline；
- 为所有 UI 改动增加新的发布 gate；
- 首批重做 Desktop 全尺寸交互。

## 28. 成功标准

完成 M1–M3 后，用户应能稳定完成：

### 时间规划链

```text
计划 → 看本周 → AI 安排 → Preview → Apply → 查看时间块 → Focus → 完成
```

### 记录行动链

```text
随手记 → 回顾 → 洞察 → 转待办 → 计划 → 安排 → 执行
```

### 学习链

```text
学习 → 课程 / Folder → 学习 Task → 计划 → Focus
```

并且用户在底部永远只需要理解五个入口：

```text
今天 | 计划 | 记录 | 学习 | 我的
```

这应成为后续新增功能时的信息架构边界：新功能优先进入现有工作空间，而不是继续增加一级导航。
