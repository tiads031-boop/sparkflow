## 2. 统一信息架构

底栏保持：日程｜待办｜记录｜学习｜我的。日程、待办恢复 SparkFlow 品牌顶栏。专注和 AI 规划作为全屏工作模式使用自身顶栏。

```text
日程：今天／周／月          → 分析：热力图／时间树／周月复盘
  今天：今日安排 + 每日随机回顾
待办：列表／四象限
记录：卡片／自由墙          → 洞察与周总结 → 生成设置
学习：目标 → 阶段／项目 → 任务 → 专注与反馈
我的：现有设置 + 关于与更新
全局 +：五个快捷标签；长按 → 语音 AI 规划
```

“今日”具体指现有日程的今天视图，不恢复第六个底栏，也不重新启用已被主路由绕开的旧 TodayView。查看其他日期时标记为当日日程，仅真实今天展示每日随机回顾。

## 3. 九项设计

### 3.1 修复随手记弹窗

已确认的代码问题：`SparksView` 外层有 `animate-page-enter`，CSS 动画以 `forwards` 保留 `transform`；记录页的 `InspirationCaptureSheet` 直接嵌在该容器内。fixed 弹层因而受变换祖先的包含块和堆叠上下文约束，不能保证覆盖 AppShell 的顶栏。当前弹层也没有最大高度、内部滚动和键盘视口适配。该路径与截图一的遮挡现象吻合，但其他入口的具体触摸／键盘表现仍需真机验证。

设计：

- 全部入口使用同一个挂到 document.body 的弹层，避免嵌在页面动画内。
- 底部圆角 Sheet，标题／关闭在顶端，正文与附件内部滚动，保存栏始终可达。
- 高度按动态可视区域限制，适配 Android 键盘和安全区；在键盘尺寸稳定后聚焦输入。
- 遮罩覆盖顶栏、底栏和快捷按钮，锁定实际页面滚动容器；弹层使用统一返回栈，Android 返回先处理键盘再关闭最上层，焦点可恢复。
- 有草稿时误触遮罩不清空内容；保存失败保留文字与附件。跨重启的离线附件队列另列增强，不把“内存保留”当作离线持久化。
- 保留现有文字、语音、图片、视频能力。上传不自动启动附件 AI 分析。

验收：从五标签入口打开、键盘开合、添加多个附件、前后台切换、保存失败重试、返回键，均无顶栏遮挡／底部按钮失联。先覆盖 360px、390px 与大字体。

### 3.2 快捷按钮：一次轻点五标签，长按平滑进入 AI

当前短按依赖 pointerup；普通 click 仅在 `detail===0` 时执行，触摸取消／移出缺少完整手势状态处理。长按为 520ms，直接打开 Planner；现有短按菜单是整张底部 Sheet，不是五个小标签。不能仅凭静态代码确定所有“不灵敏”的设备原因。

设计五个右对齐胶囊标签，沿按钮上方展开：新建任务、新建日程、随手记、开始专注、AI 规划。每项带图标、短文字，触摸高度至少 48px。窄高屏不足时压缩间距并允许菜单内部滚动，不把标签挤进状态栏。

- 轻点立即开始展开，第一帧给出按钮反馈，完整动效建议 180–240ms；标签错峰 20–30ms，主按钮旋转为关闭符号。
- 长按保留约 500ms 阈值，按下时出现渐进光环；满足阈值后触感反馈，按钮与 Planner 连续过渡约 240–300ms。准备好录音环境后启动语音，拒绝权限仍可输入文字。
- 同一手势只能触发一次：长按结束不再触发轻点；移出阈值／取消／卸载均清理计时器；键盘与读屏触发有明确入口。
- 建议主按钮仍为 56px，上移约 24px；最终定位使用底栏实际高度 + 24px 间距，safe-area 只计算一次。
- 点击空白或再按 + 关闭；进入任一业务弹层后收起菜单；减少动态效果模式取消位移动画。

### 3.3 日程取消课程表，恢复日程／待办顶栏

当前 `App.tsx` 将日程、待办传为 immersive，导致 AppHeader 被隐藏；`PlanHeader` 仍包含 timetable／课程表。

设计：视图菜单只保留今天、周、月。删除该菜单入口及主路由渲染分支，旧 `lastPlanView=timetable` 自动迁到周视图。课程事件继续显示在今天／周／月，详情、导入、调课仍有入口；本次“取消课程表”理解为取消独立视图，不删除课程数据与管理能力。

恢复品牌顶栏后压缩页面子标题留白，避免双倍 safe-area。品牌顶栏固定，日期与视图工具栏按所在滚动容器定位，弹层永远在其上方。

### 3.4 记录：卡片／自由墙；回顾迁到今日；每周洞察可配置

现状：记录页有卡片／回顾／洞察／自由墙四栏；自由墙实际是旋转卡片的网格，没有自由拖放。后端回顾按 nextReviewAt、createdAt 排序，并非随机。Insight 只手动生成，默认取最近 30 天最多 40 条记录，类型仅 theme／evolution／action，要求至少两条文字来源，没有自动每周总结任务。

**记录页**

- 主切换只保留“卡片｜自由墙”，默认卡片，记住用户选择；删除右上角随手记，创建统一走全局 +。
- 卡片：时间流、附件缩略图／语音播放器、简短标签；点击进入详情，编辑改为统一编辑界面，替换当前 prompt。
- 自由墙：同一批记录的可拖放画布，支持平移、缩放、回到全图、自动整理。默认进入可读的自动排布，明确进入整理模式后拖卡，降低拖动与滚屏冲突。
- 保存每张卡片的位置、尺寸、颜色、层次及版本；采用独立用户布局数据，不复制正文、不更改记录时间。同卡布局冲突提示重新加载，避免整面墙被旧设备覆盖。
- “洞察与周总结”作为轻量入口与最新摘要卡保留在记录工作区，不再与展示方式并列成四个主标签。

**今日随机回顾**

- 今日安排之后显示一张紧凑回顾卡，默认每天随机 3 张，可继续抽取；候选不足则显示实际数量，空时不占位。
- 尊重已有冷却：新记录次日、写想法后 3 天、稍后再看次日、已消化 14 天。随机仅发生在符合条件的记录中。
- 用户 + 本地日期保存当天抽样 ID 和完成状态，跨设备刷新不洗牌；次日重新抽取。删除或归档的记录从当天批次移除，不回填已完成项。
- 写下新理解、稍后再看、已消化、转待办都在今日回顾内完成；新的理解仍写入 Reflection。转待办先给可编辑确认卡，不因抽取自动创建任务。

**洞察设置**

- 默认周期每 7 天，建议默认周日 20:00，使用账户时区；用户可改间隔、时间、时区，可关闭自动生成并随时手动生成。首个生成时间在设置页明确展示。
- 强关联时给出少量洞察，并逐条展示来源和联系理由；没有强关联时生成“本周总结”，按真实发生内容概括，不硬凑共同主题、不强行给行动建议。
- 0 条可用内容：跳过；1 条：允许简短回顾；至少 2 条且证据成立才生成跨记录洞察。模型失败显示待重试，不能伪装成“没有关联”。
- 素材包括正文、回顾文字，以及用户已主动生成的附件转写／摘要；未转写的音频和未分析的图片只列为附件，不后台强制分析。
- 生成以服务端调度为准，App 不打开也能按期处理；保存周期窗口、时区、来源快照、运行状态及唯一生成键，避免重试／多实例重复生成。失败做有界重试，不集中补发多周旧总结。
- 原有最多 40 条截断不能直接冒充完整周总结：较大周样本分批覆盖后汇总，达到预算上限则明确展示覆盖数量。
- 自动生成与通知分别设置，通知遵守安静时段；修改周期不覆盖已生成历史。

### 3.5 专注：拖动时钟设时长，实际投入进入日程，结束后多模态记录

现状已支持 taskId 可空，但 UI 会默认选第一条任务。现在是四个时长按钮；关闭会中断。计时每秒递减，暂停只在前端，后端完成按墙钟差计算，不能可靠扣除暂停；完成请求失败被静默处理。专注服务没有将完成记录写入 CalendarEvent，也没有专注与多模态记录的关联。

**开始**：大圆形表盘，拖动外圈设置倒计时，中心同步显示分钟数；建议 5–180 分钟、5 分钟吸附，另有精确输入与 25／45／60 快捷值。默认自由专注，关联任务收进可选项；额外支持正计时用于尚不确定时长的场景。

**进行中**：表盘显示真实进度，暂停／继续、结束清晰可达；收起后保留小计时条，回到其他工作区不等于中断。减少刷新频率与动效负载。

**完成**：先确认已保存的有效专注时长，再展示“留下这次的想法”，允许文字、语音、图片、视频，亦可跳过或稍后补充。复用 Inspiration 与私有附件，不新增另一套媒体存储。记录卡与专注会话互相回链，支持一场专注多次补记。

**数据正确性**：

- 保留 PomodoroSession，新增计划时长、实际秒数、暂停累计／当前状态时间点、客户端请求 ID 与必要的有效片段；不继续用一个 duration 同时表示计划与实际。
- 以时间戳／服务端状态恢复计时，避免后台定时器停顿导致误差；暂停不计有效时长。跨设备仅一个活动会话，重试开始和结束均幂等。
- 结束时在同一事务中保存会话并创建／更新关联的 `CalendarEvent(eventType=focus)`，以会话唯一引用防重复。日程显示经过时段并标记实际专注分钟；统计只计有效片段。中途结束可保存已投入时长，不虚报完成预设目标。
- 专注附件稍后保存失败，不回滚已完成计时；网络失败明确显示待同步，客户端持久保存必要状态并可重试。
- 与已安排任务时间重叠是计划和实际的叠加，不算新的排程冲突，也不能在热力图重复相加。
- Android 恢复时重新计算时间。若要锁屏结束铃声准确可靠，需要原生通知／计时能力配合；不能仅靠 WebView 的 setInterval 承诺准确提醒。

### 3.6 复用 DeepTutor 搜索服务

用户已说明搜索服务部署在腾讯云。本轮受“仅使用本地 GitHub CLI”限制，没有进入服务器查看配置，因此结论为：SparkFlow 代码已有可复用搜索接口；实际 DeepTutor 服务类型、地址、鉴权、容器网络、可用性尚未确认。

已确认：SearxngSearchProvider 读取 SEARXNG_BASE_URL，以 `/search?q=...&format=json` 获取结果，12 秒超时；WebResearchService 将标题、URL、摘要、抓取时间和有效期写入规划证据。搜索服务与文字生成模型分开。最新文字模型选择不会自动提供搜索。

实施时先在另行开放的服务器访问范围内做只读核实：

1. 若 DeepTutor 使用 SearXNG 且允许 JSON 搜索，复用其内网端点，配置 SparkFlow API；若服务要求鉴权，补受控服务端鉴权配置。
2. 若使用其他搜索网关或供应商，在现有 SearchProvider 下新增适配，不复制 DeepTutor 的数据库、用户态或整套 AI 工作流。
3. 从 SparkFlow 容器验证 DNS／网络、鉴权、中文查询、来源 URL 和错误降级；使用独立服务凭据／额度边界，密钥不传客户端。
4. 搜索失败显示“未完成联网核实”，不能让模型宣称已搜索。官方来源优先需真正落实排序／过滤：目前 provider 接收相关标记却未执行优先逻辑，域名分类也不是事实真实性证明。

搜索首先用于 AI 规划与学习目标；私人记录周总结默认仅使用用户记录，不自动向搜索引擎发送原文。

### 3.7 AI 规划依据浮在顶栏下方，液态玻璃表现

现状：`PlannerSheet` 将依据块渲染在消息列表之后，同属滚动内容，所以随对话变长落到底部。

建议布局：

```text
返回    当前规划名称         新规划
        文字模型选择
   [ 当前规划依据 · 3 条约束   展开 ]  ← 顶栏下方常驻玻璃卡
             对话滚动区域
             输入栏／语音
```

- 依据卡从消息流中提取，放到顶栏下方独立区域，成为内容最上方的常驻摘要；不会随着新消息跑到底部。
- 半透明底、背景模糊、细亮边、柔和阴影；左右 12–16px 留白、约 20px 圆角、收起高度约 52px。深色模式对应调整，低性能／无 blur 支持时退化为不透明表面。
- 点击展开目标、约束、偏好、策略、假设、证据；展开高度最多约可视区域的 40%，内部滚动。编辑仍保留 revision 并发保护。
- 依据变化只给轻提示，不自动反复展开；revision 放详情而不是日常摘要。文字模型选择沿用最新提交，必要时压成顶栏胶囊节省高度。
- 不遮第一条消息、不抢输入焦点；打开键盘后保持收起摘要，输入栏可达。

### 3.8 底栏图标适量放大

当前图标仅 17px。建议提升到 22px，激活态约 23–24px；文字 10px → 11px；点击高度至少 48px，选中背景约 42×32px。保持五项稳定排列，按底栏最终实际高度联动正文底部留白与快捷按钮，不用多个互不一致的常量。

### 3.9 安卓更新与检查更新

现有 workflow 已构建并发布 commit 命名的 debug prerelease，但 Gradle 固定 versionCode=1、versionName=1.0；设置页版本也写死 v1.0。APK 文件名有 SHA 不等于 App 内版本信息完整，更不足以形成可靠更新通道。

设计入口：“我的 → 关于与更新”，展示安装版本、构建号、更新通道、检查更新、更新说明、下载状态。诊断信息可展开，默认不展示技术栈清单。

- CI 写入单调递增 versionCode、可读 versionName、build SHA，App 读取真实原生版本。
- 首先确认现有安装包签名与发布凭据。后续使用持久化签名密钥，验证证书一致才支持覆盖升级；不能用每次临时 debug 签名承诺无损更新。
- 生成受控更新清单：版本号、构建号、通道、APK 地址、大小、SHA-256、最低兼容版本和说明；只有构建／校验成功才发布清单。
- 不依赖 GitHub `releases/latest` 获取当前全为 prerelease 的包，也不按 SHA 字典序判断新旧。按明确的 stable／preview 通道及构建号比较。
- 用户点击后下载，校验后交由系统安装器；安装授权由 Android 正常处理，取消后可继续使用。若旧包签名不兼容，明确告知并先保护本地数据，不自动卸载。
- 手动检查为必备；可选启动时每天检查一次，失败不阻塞启动、不误报为最新。Web/PWA 使用自己的版本刷新流程，避免展示 APK 安装按钮。
- 每阶段验证后可提供预览 APK，最终更新包与确认的源码 SHA 一致。Web、API migration、Android 分别核对，APK 构建成功不等于真机全部验收。

## 4. 热力图、树状图与旧计划如何融合

最新统一设计的 M10.2 已提出这两项；代码主链尚未实现相应分析页面。本轮将它们接到真实专注数据完成之后，而不是把尚不正确的 duration 直接画图。

### 热力图

入口：日程右上方“分析”，默认近 13 周，可切年度。四个独立指标：计划分钟、已完成任务的估算分钟、课程负荷、有效专注分钟。实际专注不能与任务估算合并为“真实完成时长”。日期按用户时区切分，跨午夜按有效片段分摊；课程按真实 occurrence 去重。点击格子定位对应日程并展示构成；图例单位与统计覆盖范围清晰。

### 时间树

入口：日程分析的“时间树”；学习目标详情也能打开同一棵树的子树。

```text
目标（现有 StudyFolder）
  阶段／项目（现有 Task.project）
    任务（共享 Task）
      专注会话（真实有效时长）
        专注后记录（按需展开）
自由专注
  未关联任务的会话
```

移动端采用纵向可折叠树，不做必须横向拖到很远才能读完的脑图。无目标任务归到独立项目／未分类；自由专注无需为了进树而强行绑定目标。若一条任务属于多个目标，全局总量按会话 ID 去重，目标内允许查看但提示共享归属。

长期知识树与时间树含义不同。知识点、练习正确率、遗忘曲线需要真正的 StudyUnit／Attempt 等数据，目前只是设计；保留为学习闭环后续阶段，不能用项目名冒充掌握度。

### 旧方案取舍

| 旧内容 | 本轮处理 |
|---|---|
| 热力图、时间树、周/月复盘 | 纳入专注数据闭环后的分析阶段 |
| 卡片回顾、Reflection、Insight 来源关系 | 复用，迁移入口并增加随机与周期生成 |
| 课程表独立视图、日程隐藏品牌顶栏 | 按本次要求替代 |
| Today 的多个统计卡、旧节奏仪表 | 不恢复；今日只加紧凑回顾 |
| 四象限、甘特图 | 保留已有能力，不新增底栏或重复任务数据 |
| AI Session 历史抽屉／归档 | 后续独立批次，依据卡先使用现有 Thread |
| 学习知识树／练习／复习队列 | 保留长期路线，待真实学习数据模型落地 |
| PDF、年度导出、Android Widget | 后续增强，不阻塞本轮九项 |

## 5. 实施拆分与验收

| 批次 | 交付 | 核心验收 |
|---|---|---|
| A 交互修复 | 弹层、五标签、长按过渡、按钮上移、顶栏、移除课程表、图标、玻璃依据卡 | 短按／长按仅触发一次；键盘与返回键正确；360px 无遮挡；旧视图偏好可迁移 |
| B 记录重整 | 卡片／自由墙、每日随机回顾、洞察设置与周总结 | 跨设备当日抽样稳定；拖放布局恢复；无强关联不凑洞察；周期生成幂等；来源归属校验 |
| C 专注闭环 | 拖表盘、自由专注、可靠暂停／恢复、日程落点、多模态复盘 | 暂停不计时；提前结束显示实耗；断网重试不重复日程；后台恢复准确；附件失败不丢专注 |
| D 分析 | 热力图、时间树、基础周/月复盘 | 跨午夜与时区准确；自由专注可见；计划与实际不重复累计；汇总可追溯到源记录 |
| E 搜索与发布 | 核实腾讯云搜索服务、适配／配置、安卓更新页与发布链 | SparkFlow 容器真实搜索成功；超时有降级；版本与签名可覆盖升级；清单对应确切 APK |

E 的搜索只读核实、安卓版本基础可以在开发前段开展；最终 APK 随已验收功能发布。合并前以正常 Web/API 测试、相关交互回归及数据库测试验证，不因纯视觉参数新增冗余测试。

涉及数据库的候选变更：每日回顾批次、自由墙布局、周期洞察运行记录、Insight summary 类型／周期元数据、Pomodoro 精确计时字段／片段、专注与 CalendarEvent／Inspiration 回链。均采用增量迁移；历史专注保留原有分钟并标注精度，不能伪造过去暂停片段。

记录、任务、课程、专注仍使用原事实源。日程分析是读模型；Focus 对应 CalendarEvent 是有唯一引用、随会话同步的日历投影，不独立编辑成另一份真相。

## 6. 本轮建议确认的默认值

确认本方案即按以下默认设计推进：课程表仅取消视图；今日回顾默认 3 张；洞察默认每周日 20:00、周期可改；自由墙可拖放且保存布局；专注默认不关联任务、实际时长写入日程；热力图与时间树包含在本轮分阶段范围内。

腾讯云搜索服务的实际接通仍依赖服务器配置核实；本轮 GitHub CLI 资料不足以证明服务可用。服务器访问方式在实施时按用户允许的工具范围处理。
