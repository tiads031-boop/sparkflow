# SparkFlow VNext M4–M8：AI 调度中枢、目标学习、课程变动、多模态记录与界面重整

> 状态：方案确认稿  
> 基线：`master@73e5f779`  
> 目标：把 SparkFlow 从“多个功能入口”收敛为“记录 → 澄清 → 规划 → 排程 → 提醒 → 调整”的统一闭环。

---

## 1. 本轮产品结论

### 1.1 五个一级工作空间保持不变

底部导航仍固定为：

1. **今天**
2. **计划**
3. **记录**
4. **学习**
5. **我的**

但各空间重新定义：

| 空间 | 新职责 | 不再承担 |
| --- | --- | --- |
| 今天 | 只回答“今天要做什么” | 日期浏览、节奏盘、空闲时间、今日进度 |
| 计划 | 任务、日程、课程、四象限、AI 调度 | 另起一套 AI 日程事实源 |
| 记录 | 文字 / 语音 / 图片 / 视频快速捕捉，后续转任务/目标 | 仅文本灵感墙 |
| 学习 | 独立的目标型 AI 学习规划 | 课程聚合、课程入口镜像 |
| 我的 | 账户、外观、通知、集成、数据、诊断 | 旧导航自定义配置 |

### 1.2 核心闭环

```
记录一个想法 / 新建任务 / 建立学习目标 / 课程临时变动
              ↓
      AI 判断是否需要追问
              ↓
        1~3 个必要问题
              ↓
       生成“理解卡 + 方案预览”
              ↓
 用户确认 / 修改 / 继续和 AI 对话
              ↓
      Preview → Apply → Undo
              ↓
       进入真实任务与真实日程
              ↓
          通知与执行
              ↓
   随时再次自然语言调整
```

**重要约束：**
- AI 永远不建立第二套 Task / Course / Calendar 事实源。
- AI 对真实日程的写入必须经过 Preview → Apply。
- 临时预览只存在前端/计划草稿中；Apply 后才写 Task / CalendarEvent / Course override。
- 已有 `SchedulePlan` 继续承担 Apply / Undo 快照。
- 已有 `AIConversation` 继续记录对话，不新增重复的聊天事实表。

# 2. “学习”重做：从课程聚合改为 AI 目标规划

## 2.1 新定位

“学习”不再自动读取或展示现有课程，也不再出现“今日课程 / 课程管理 / 关联课程”。

它只处理：

- 我要学会什么；
- 我现在是什么水平；
- 什么时候希望达到；
- 每周可以投入多少时间；
- 我偏好什么节奏；
- AI 如何拆阶段、拆任务并安排到日程。

示例：

> “我想 12 月前通过六级，现在词汇量大概 4500，每周能学 5 小时。”

AI 不立即生成一堆任务，而先判断缺失信息，例如：

- 目标日期是否固定？
- 听力/阅读/写作哪个最弱？
- 工作日和周末可用时间分别是多少？
- 是否已有材料？

最多追问必要问题，不做冗长问卷。

## 2.2 学习主页

学习页建议只保留三层：

### A. 进行中的目标

卡片展示：
- 目标名称；
- 截止日期；
- 当前阶段；
- 本周计划完成度；
- 下一次学习安排；
- “继续和 AI 规划”。

### B. 本周学习安排

只显示由学习目标生成的普通 Task：
- 时间；
- 标题；
- 预计时长；
- 目标来源。

这些 Task 仍然是系统现有 Task，只是 `section = study`，不再通过 `courseId` 判断是否属于学习。

### C. 新建学习目标

入口：
- “告诉 AI 我想学什么”
- 可先只输一句话。

## 2.3 数据策略

第一阶段不删除现有 `StudyFolder`，避免破坏已有数据。

将其升级为“学习目标容器”，新增必要字段：

- `objective`：目标结果；
- `deadline`；
- `currentState`；
- `weeklyMinutes`；
- `planningState`：draft / planned / active / paused / done；
- `aiBrief Json?`：保存用户确认过的结构化目标信息。

继续复用：
- `StudyFolderTask`：目标与 Task 的关系。

停止在新 UI 中使用：
- `StudyFolderCourse`。

旧关系保留只为兼容，不再作为产品逻辑入口。

## 2.4 AI 目标规划输出

AI 输出必须分三层，而不是直接堆任务：

1. **阶段**：例如“词汇补强 / 真题适应 / 冲刺”；
2. **里程碑**：例如“完成 10 套听力训练”；
3. **可执行 Task**：真正写入系统的任务。

只有第 3 层进入 Task 与日程。

# 3. AI 安排 2.0：从“固定表单”变成统一调度助手

## 3.1 当前问题

现有“AI 帮我安排”主要让用户选择日期、可用开始/结束时间，然后生成排程。

问题是：
- 用户需要先替 AI 结构化需求；
- 不能自然表达临时想法；
- 不能灵活调课；
- 不能围绕目标连续对话；
- 不能很好地解释“为什么这样安排”。

## 3.2 新入口名称

建议把“AI 帮我安排”统一改成：

**AI 规划与调整**

Quick Add 中拆成：
- 新建任务
- 新建日程
- 随手记
- **临时安排**
- **AI 规划与调整**
- 开始专注

“临时安排”是轻量入口，“AI 规划与调整”是完整入口。

## 3.3 对话式工作流

AI 规划与调整同时支持 **文字输入与语音输入**。

### 语音输入原则

- 输入框右侧提供麦克风入口；
- 点击或长按开始录音，再次点击结束；
- 语音先转写成文字，**默认先展示转写结果，不直接执行**；
- 用户可以修改转写文字后再发送；
- 发送后进入与文字输入完全相同的“澄清 → 理解卡 → Preview → Apply → Undo”链路；
- 原始音频默认只用于本次转写，不永久保存；
- 用户可主动选择“同时保存到记录”，此时才作为 Inspiration 的 audio attachment 保存；
- 转写失败时保留录音状态并允许重试，不创建空任务/空日程；
- Android / PWA 都必须有麦克风权限说明与拒绝后的文字输入降级路径。

用户可以直接说：

- “今晚想背 30 分钟单词，别太晚。”
- “这周帮我找时间把民法论文写完。”
- “明天下午突然有事，把能挪的安排一下。”
- “把周四的知识产权法调到周五下午。”
- “我想开始准备法考，帮我做个计划。”

AI 首先返回一个**理解卡**：

> 我理解为：  
> - 新增任务：背单词  
> - 时长：30 分钟  
> - 时间范围：今晚  
> - 约束：不要太晚  
>   
> 还缺一个信息：最晚几点结束？

用户回答后才生成 Preview。

## 3.4 语音输入交互

建议交互：

1. 用户点击麦克风；
2. 显示实时录音状态、时长和“取消 / 完成”；
3. 完成后进入“正在转写”；
4. 展示可编辑转写文本；
5. 用户点击“发送给 AI”；
6. AI 判断是否需要追问；
7. 如需追问，用户后续仍可继续用语音回答。

语音输入不能绕过确认：
- “把明天下午所有任务往后挪”即使识别成功，也只能先形成候选操作；
- 涉及课程调换、批量移动任务等操作，仍必须显示 Preview。

实现上优先复用同一 Conversation 输入组件，不单独做一套“语音 AI”页面。

## 3.5 意图路由

统一 AI 助手内部至少支持：

- `capture_to_task`：把临时想法转成任务；
- `schedule_task`：给任务找时间；
- `rebalance_day`：重新整理某天可移动任务；
- `reschedule_course`：临时调课；
- `swap_course`：两节课程交换；
- `goal_plan`：学习目标规划；
- `goal_replan`：学习计划调整；
- `explain_schedule`：解释为什么这样排。

用户不需要看到 intent 名。

## 3.6 Preview 设计

Preview 继续叠加在 Plan Week / Agenda 中，但需要升级：

- 原安排：浅灰；
- 拟新增：紫色虚线；
- 拟移动：原位置淡化 + 新位置虚线；
- 冲突：红色边框；
- 锁定项：明确说明不能移动；
- 每一项可单独取消；
- 支持“全部应用”“继续和 AI 调整”。

Apply 后：
- 写入真实 Task / CalendarEvent；
- 保存 `SchedulePlan.beforeState / afterState`；
- 显示 Undo。

# 4. 临时想法 / 临时任务安排

这是 Quick Add 的高频场景，不能要求用户先创建任务再去 AI 排程。

## 4.1 流程

用户点“临时安排”：

> “下午记得去拿快递，顺便买打印纸。”

系统做两步：

1. AI 提取候选动作：
   - 拿快递；
   - 买打印纸。
2. 判断是否需要追问：
   - “预计一共需要多久？”
   - 如果当前时间与地点已经足够，可直接建议时间。

随后出现：
- **只记下来**
- **转成任务**
- **安排到今天**

三个明确选择。

## 4.2 分类原则

- 纯想法 → Inspiration；
- 明确行动但暂不排期 → Task；
- 明确行动且用户要求安排 → Task + Preview；
- AI 不应未经确认直接把“想法”变成“待办”。

# 5. 课程系统：调课、换课、停课、补课 + AI 自然语言调整

## 5.1 Course 与 Study 完全分开

Course 只处理真实课程：
- 学期课程；
- 上课时间；
- 地点；
- 老师；
- 课程任务；
- 临时变动。

学习目标不再依赖 Course。

## 5.2 四种变动

### 调课
某一次课程从 A 时间改到 B 时间/地点。

### 换课
两个具体 occurrence 对调。

### 停课
某一次 occurrence 不上。

### 补课
额外增加一次 occurrence。

## 5.3 不能直接修改 Course 模板

用户说：

> “这周四民法改到周五。”

只能修改本周 occurrence，不能改变以后每周四的基础课程模板。

只有当用户明确说：

> “以后民法都改到周五。”

才进入“修改课程规则模板”的确认流程。

## 5.4 数据实现

现有 `CalendarEvent.isOverride` 已经具备基础，但单靠布尔值不足以可靠表达“哪一次原课程被覆盖”。

建议给 CalendarEvent 增加：

- `overrideType`：reschedule / cancel / swap / extra；
- `overrideOriginalStart`：被替换 occurrence 的原始开始时间；
- `overrideGroupId`：换课时关联成组。

这样：
- 原 Course 仍是规则模板；
- CalendarEvent override 是具体日期例外；
- 不需要建立第二套课程系统。

## 5.5 AI 调课

用户说：

> “把明天上午公证法换到周五三四节。”

AI：
1. 找到具体课程；
2. 找周五三四节是否冲突；
3. 如冲突，列出冲突；
4. Preview 显示“原位置 → 新位置”；
5. 用户确认后写 override；
6. 可 Undo。

# 9. 随手记：升级为多模态 Inbox

## 9.1 输入方式

记录页 / Quick Add 支持：

- 文字；
- 语音；
- 图片；
- 视频。

第一阶段不必上复杂编辑器。

## 9.2 附件数据

新增通用 `InspirationAttachment`：

- id
- inspirationId
- type: image / audio / video
- storageKey
- mimeType
- fileName
- size
- duration
- width / height
- transcript
- thumbnailKey
- createdAt

Inspiration 仍是主记录，附件只做从属资源。

## 9.3 存储

优先用现有自托管 API 服务器：
- 文件写到持久化目录；
- Nginx / API 提供受控读取；
- 数据库只存 metadata，不存大文件 blob。

建议限制：
- 图片：10 MB；
- 音频：50 MB；
- 视频：200 MB（可先从更低上限开始）。

## 9.4 AI 能力

后续可在用户明确触发时：
- 音频转文字；
- 图片提取信息；
- 视频基于转录生成摘要；
- 一键“变成任务 / 加入学习目标 / 交给 AI 安排”。

不要在上传时默认消耗 AI 额度。

# 10. 通知提醒重做

## 10.1 先修 P0：按用户隔离任务提醒

当前 `PushService.notifyDueTasks()`：
- 查询到期任务时没有按 user 分组；
- 后续遍历全部 PushSubscription。

下一实现批次必须首先改为：
- 查询任务时包含 `userId`；
- 按 `userId` 分组；
- 只向该用户 subscriptions 推送对应任务。

这是隐私与正确性问题，优先于 UI。

## 10.2 reminderAt 才是主要提醒时间

现有 cron 主要依据 `dueDate` 的 30 分钟窗口。

改为：
1. 有 `reminderAt` → 以 reminderAt 为准；
2. 无 reminderAt → 可使用用户默认规则推导；
3. dueDate 只是截止，不等于提醒。

## 10.3 通知设置中心

设置 → 通知与提醒：

- 总开关；
- 任务提醒；
- 课程提醒；
- 学习计划提醒；
- 每日计划摘要；
- 临近冲突提醒；
- 安静时段；
- 默认提前时间；
- “发送测试通知”。

Android / PWA 共用同一偏好，底层按平台选 FCM / Web Push / Local Notification。

## 10.4 防重复

增加 notification delivery key：
- userId + sourceType + sourceId + reminderAt。

同一提醒只能发送一次。

# 14. 验收标准

## 今天
- 不出现日期选择；
- 不出现 Rhythm / FreeTime / 今日进度；
- Plan 浏览其他日期后返回 Today，仍是实际今天。

## 四象限
- 360px 手机一次看到完整 2×2 结构；
- 可以关闭四象限模式；
- 模式切换不丢任务。

## AI
- 用户可以用文字或语音一句话发起；
- 语音必须先转写并允许用户编辑，不能识别完直接 Apply；
- 麦克风权限拒绝后仍能完整使用文字输入；
- 信息足够时不强行追问；
- 信息不足时只问必要问题；
- Apply 前不改真实 Task/Calendar；
- Apply 后可 Undo。

## 学习
- 页面不展示 Course；
- 新建目标不要求选择 Course；
- AI 生成的执行项仍是普通 Task。

## 课程
- 单次调课不改变之后的固定课程；
- 换课可以同时预览两个 occurrence；
- 冲突必须提示；
- AI 和手动操作产生同样的 override 数据。

## 记录
- 文字/图片/音频/视频都可创建 Inspiration；
- 附件失败不应造成空记录；
- 删除记录时附件按明确策略处理。

## 通知
- A 用户永远收不到 B 用户任务标题；
- reminderAt 可以独立于 dueDate；
- 相同提醒不重复发送；
- PWA / Android 都可发送测试通知。
