# 首页入口与自然语言日程衔接改进

日期：2026-10-14。基于 `master@8b790e3`。实施分支：`feat/home-navigation-layout`。

## 入口布局

首页顶部用“今天⌄”统一选择今天、周视图、月视图、日程列表、甘特图；右侧提供有文字的“AI 规划”。原来混合视图、实际记录、分析报告的四项胶囊移除。

时间分析位于时间轨道右上；实际记录位于轨道下方。混合展示日程、随手记、专注的区域改称“今日动态”。底栏统一显示图标与文字：日程（CalendarDays）、待办（ListTodo）、记录（NotebookPen）、学习、我的。

日程视图在 App 中保存，切换模块不强制返回今天；非今天视图提供独立的日期导航与“回到今天”。实际记录提供返回按钮；分析→实际记录→返回保留原来的页面栈和日期。主滚动容器按视图/日期保存位置，异步内容加载后恢复。底栏高度调整为 72px，FAB 位于安全区上方 104px，内容留足空间以滚出最后一条卡片。视图选择面板支持当前项标记、Esc、焦点恢复与 Tab 循环。

## 自然语言规划

AI 现在接收页面选中的日期、浏览器时区、日程类任务和非课程固定日历事件。此前任务查询排除了 `section=calendar`，导致对“已有日程”的理解不完整。

交互和提示词明确区分：

| 用户意图 | 行为 |
|---|---|
| 查看当天安排、检查冲突 | 从已有日程回答，不生成写入动作 |
| 新增明确事项 | 生成待确认任务；有执行时间则写入成对的 scheduledStart/End 草案 |
| 移动现有事项 | 使用真实 taskId 更新，不创建替代任务；只改开始时间时保留时长 |
| 移出日程 | 清空成对排期字段，保留任务；锁定或重复任务需从编辑界面明确处理 |
| 设置安排偏好 | 写入当前 PlanningThread 的约束/偏好，后续沿用；不宣称修改全局设置 |
| 安排已有未排期待办 | 生成精确时间范围和 taskIds 的 scheduleRequest，通过现有排程器预览 |
| 临时冲突重排、调课、停课 | 保留既有重排和课程变动能力，将待确认操作及撤销入口直接展示 |

“今天/明天/今晚”根据真实当前时间与时区解释；“当天/这一天/当前日期”根据页面日期解释。模糊的任务指代、固定时间冲突或影响结果的关键缺项需要澄清；已确认信息不反复询问。长期目标继续使用原对话规划，不因入口调整新增一套任务系统。

新增 `scheduleRequest` 是可选协议字段，旧客户端和旧模型响应仍兼容。范围至多 7 天，只能引用当前用户快照中未排期、未锁定任务。前端向 `/planner/preview` 同时传递 threadId 和 taskIds，避免跨学习目标或把无关待办一起排入。偏好保存后的回应不再自动出现“安排全部待办”的通用按钮。新创建但未排期的任务提示用户继续提供可用时段。

规划输入支持中文输入法组成中的 Enter，避免候选字确认时误发送。用户在唯一日程预览后明确回复“确认，全部执行”，直接应用该预览，避免重新生成第二份草案。

## 确认时的日程校验

直接任务草案在同一数据库事务中重新读取真实占用，验证完整起止时间、同一任务重复变更、批次内部重叠、已有任务及有效日历事件冲突。调整锁定或重复任务会给出明确编辑提示。更新草案携带任务 updatedAt，并在实际 updateMany 条件中校验，防止覆盖草案生成后的修改；事务使用 Serializable。

已取消的课程实例不再作为自动排程/重排/应用时的固定占用。任务、课程和重排操作应用后刷新任务/课程数据并派发日历变更事件。

- 尚未完成：真实账号下 Qwen/当前提供商的自然语言效果、PWA/Android 真机、服务器发布与公网验收。未改数据库 schema，无新增 migration。
